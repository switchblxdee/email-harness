# mail_harness

Харнесс для почтовых агентов. **IMAP** читает новые письма, **агент** решает, что с ними делать, **харнесс** выполняет решение: отвечает через **SMTP**, сохраняет файлы, перемещает письма. Работает только на стандартной библиотеке Python 3.11+, ставить ничего не нужно.

```
IMAP ──> парсинг ──> фильтр роботов ──> АГЕНТ ──> [действия] ──> safety ──> SMTP / файлы / IMAP
                                         ▲                          │
                          твой код, LLM, HTTP-сервис       лимиты, петли, dry-run
```

Агент **ничего не делает сам**: он только возвращает список действий. Благодаря этому любой агент, включая LLM, работает внутри одних и тех же ограничений: dry-run, лимиты, запрет отвечать роботам, запрет писать за пределы `data_dir`.

## Быстрый старт

Нужен Python 3.11+. Ядро харнесса работает только на стандартной библиотеке. Зависимости из `requirements.txt` нужны для LLM-агентов из `examples/` и для чата Task Helpy.

```bash
git clone <url> && cd email-harness
pip install -r requirements.txt        # только для LLM-агентов и чата

cp config.example.toml config.toml     # вписать host/username
cp .env.example .env                   # вписать MAIL_PASSWORD и OPENROUTER_API_KEY

python3 -m mail_harness check          # проверить IMAP и SMTP
python3 -m mail_harness folders        # имена папок (в том числе русские)
python3 -m mail_harness run --once     # один проход в dry-run
python3 -m mail_harness run            # постоянный опрос (по умолчанию dry-run)
python3 -m mail_harness run --live     # боевой режим
```

При первом запуске старые письма не трогаются (`start_from = "now"`): обрабатывается только то, что придёт после старта.

В **dry-run** ответы не уходят, а сохраняются в `data/dry_run/<uid>_reply.eml`: их можно открыть в почтовом клиенте. Флаги и перемещения писем тоже не выполняются. Файлы (вложения, `task.json`) при этом сохраняются.

## Агент «бэклог» (готовый)

`mail_harness.agents.backlog:BacklogAgent` срабатывает, если в письме есть `.xlsx/.xls/.xlsm/.csv` и ты стоишь в «Кому». Тогда он:
1. отвечает: «Здравствуйте! Егор Иванович получил сообщение. Кинул Ваш запрос ему в бэклог. Сообщение создано автоматически.»;
2. создаёт папку `data/backlog/2026-09-27_1030_<тема>_<uid>/` и кладёт в неё вложения и `task.json`:

```json
{ "title": "Отчёт за квартал", "description": "<текст письма>", "from": "Иван Петров <ivan@corp.ru>",
  "received": "2026-09-27T10:30:00+00:00", "files": ["отчёт.xlsx"], "status": "new" }
```

Эти `task.json` потом будет читать календарь. Настраивается в `[agent.options]`: текст шаблона, расширения, `move_to`, `reply_all`.

## Свой агент

```python
# my_agent.py
from mail_harness import Reply, Skip, Flag, SaveAttachments

class MyAgent:
    def __init__(self, greeting="Добрый день"):   # параметры из [agent.options]
        self.greeting = greeting

    def handle(self, email, ctx):
        if "срочно" not in email.subject.lower():
            return [Skip("не срочно")]
        return [Reply(f"{self.greeting}! Увидел, займусь."), Flag("\\Flagged")]
```

```bash
python3 -m mail_harness try письмо.eml --agent my_agent:MyAgent   # отладка без сети
python3 -m mail_harness run --agent my_agent:MyAgent
```

Что есть у агента:
- `email.subject`, `email.text`, `email.html`, `email.sender`, `email.to`, `email.cc`, `email.date`, `email.attachments` (с полями `filename`, `extension`, `data`, `inline`), `email.thread_id`, `email.header("X-...")`;
- `ctx.is_addressed_to_me(email)`, `ctx.dry_run`, `ctx.data_dir`, `ctx.log`.

Какие действия можно вернуть:

| Действие | Что делает |
|---|---|
| `Reply(body, html=None, reply_all=False, quote_original=True, subject=None, attachments=())` | ответ в ту же ветку |
| `SaveAttachments(directory, extensions=(), include_inline=False)` | сохраняет вложения в `data_dir/directory` |
| `WriteFile(path, content)` | записывает файл в `data_dir/path` |
| `Flag("\\Seen")` / `Flag("\\Flagged")` | ставит флаг на письмо |
| `Move(folder)` | перемещает письмо в папку (выполняется последним, не больше одного) |
| `Skip(reason)` | ничего не делает, причина пишется в лог |

Необязательные методы: `setup(ctx)` вызывается при старте, `close()` при остановке. Удобно, чтобы, например, загрузить модель один раз.

## Агент на LangGraph

Граф подключается через `mail_harness.agents.langgraph:LangGraphAgent`. В `graph` указывается скомпилированный граф или функция, которая его возвращает.

**Режим `messages`** подходит для чат-агентов (`create_react_agent` или граф на `MessagesState`). Письмо приходит в граф как сообщение пользователя, последний ответ ИИ становится ответом на письмо. Если граф ответил `SKIP`, письмо пропускается.

```toml
[agent]
class = "mail_harness.agents.langgraph:LangGraphAgent"
[agent.options]
graph = "my_agent.graph:graph"
system_prompt = "Ты ассистент Егора Ивановича. Отвечай кратко и вежливо."
```

**Режим `state`** подходит для графа со своей логикой. Граф получает `state["email"]` (dict) и должен положить в `state["actions"]` список действий: объекты `Reply/Move/...` или dict'ы `{"type": "reply", "body": "..."}`.

```toml
[agent.options]
graph = "my_agent.graph:make_graph"
mode = "state"
# input_key = "email"; output_key = "actions"; include_attachments = true — файлы придут в base64
```

Если у графа есть checkpointer, адаптер передаёт `thread_id` = ветка письма, так что агент помнит переписку. Для асинхронных графов добавь `use_async = true`.

### Пример: `examples/openrouter_agent.py`

Класс `MailAgent`: граф LangGraph на OpenRouter (triage → задача в бэклог / вежливый ответ на вопрос / пропуск). Узлы графа — методы класса, `handle()` — точка входа для харнесса, адаптер не нужен. Требует `pip install langchain-openai`.

```bash
export OPENROUTER_API_KEY='sk-or-...'
python3 -m examples.openrouter_agent examples/emails/task_excel.eml                       # только граф
python3 -m mail_harness -c examples/openrouter.toml try examples/emails/task_excel.eml   # через харнесс
```

## Агент на другом языке / LLM-сервис: HttpAgent

```toml
[agent]
class = "mail_harness.agents.http:HttpAgent"
[agent.options]
url = "http://localhost:8000/handle"
include_attachments = false   # true — файлы уйдут в base64
```

Харнесс отправляет `POST {"email": {...}, "dry_run": true}` и ждёт в ответ `{"actions": [{"type": "reply", "body": "..."}, {"type": "move", "folder": "Бэклог"}]}`.
Типы действий: `reply`, `save_attachments`, `write_file`, `move`, `flag`, `skip`.


## Защита (агент не может её обойти)

- **Роботы не попадают к агенту:** автоответы, рассылки, NDR, `noreply@`, письма от себя (`Auto-Submitted`, `Precedence`, `List-*`, `X-Auto-Response-Suppress` и др.).
- **Наши ответы помечены** `Auto-Submitted: auto-replied` и `X-Auto-Response-Suppress: All`, чтобы чужие автоответчики на них не отвечали.
- **Лимиты:** один автоответ на ветку; не больше N в час одному человеку и M в час всего.
- **`allowed_domains`:** отвечать только коллегам.
- **Повторы после сбоя:** если SMTP упал, письмо обработается ещё раз, но ответ не продублируется. После `max_attempts` неудачных попыток письмо пропускается, чтобы одно «битое» письмо не блокировало очередь.
- **Файлы:** имена вложений санитизируются, запись за пределы `data_dir` запрещена.

Всё, что происходило, записывается в `state.sqlite3`: таблицы `processed` (статус каждого письма) и `replies` (кому и когда отвечали).

## Бэклог в браузере и работа в фоне

```bash
python3 -m mail_harness serve            # почта + интерфейс: http://127.0.0.1:8766/
python3 -m mail_harness serve --live     # то же, но с настоящими ответами
python3 -m mail_harness serve --no-mail  # только интерфейс, без почты
```

Один процесс проверяет почту и показывает бэклог:
- **доска** «Новые / В работе / Готово»: карточки перетаскиваются мышкой, задачи с ближайшим сроком выше;
- **календарь** по срокам (`due_date`); задачи без срока стоят по дате письма;
- **карточка задачи**: суть, текст письма, файлы (кнопка «Открыть» запускает Excel), папка задачи, заметки;
- поиск (`/`), автообновление, индикатор почты (работает / dry-run / ошибка);
- **статистика**: задачи, чат, токены и почта за 7 / 30 / 90 дней или за всё время. Подробнее ниже;
- **настройки** (шестерёнка): профиль, пять тем оформления, память ассистента. Подробнее ниже.

Статус и заметки сохраняются в `task.json` задачи. Интерфейс доступен только с этого компьютера (`127.0.0.1`). Если почта не настроена или упала, интерфейс всё равно работает, а причина видна в индикаторе.

### Чат с Task Helpy

Кнопка «Task Helpy» в шапке бэклога (или ⌘/Ctrl + J) открывает чат с LLM-агентом (`examples/chat_agent.py`, LangGraph + OpenRouter).

**Что умеет:**
- **Встречи:** письма про встречи и созвоны становятся задачами-встречами с датой и временем, они видны в календаре.
- **Отвечать на вопросы:** «что у меня на сегодня», сводки, «что пришло на почту за сутки».
- **Читать вложения:** Excel (с датами и процентами) и CSV, например «в каких филиалах расхождение больше 5%».
- **Редактировать доску и календарь:**
  - создать задачу;
  - поменять название, описание, суть, приоритет, срок, статус;
  - добавить заметку;
  - удалить задачу.

  «Перенеси на пятницу» он переводит в конкретную дату, и задача переезжает в календаре.

**Ответы людям.** «Ответь Анне, что буду на встрече» даёт карточку с черновиком письма. Текст можно поправить прямо в карточке, потом нажать «Отправить». Письмо уходит только автору задачи, в ту же ветку, и только после подтверждения. Отправленные ответы видны в карточке задачи («Ваши ответы»).

**Живой контекст.** Перед каждым ответом Task Helpy получает свежий снимок бэклога и список того, что пришло с твоего прошлого сообщения. На «что нового?» он отвечает сразу, без поиска. Новые задачи появляются в чате строкой «Новая задача / встреча от …», а если чат закрыт — точкой на кнопке.

Как ассистент понимает, что новое:
- «Новое» — это задачи и UPD, которых он ещё не видел. Дата письма роли не играет, поэтому письмо, которое долго разбиралось или пришло с неточным `Date`, не теряется.
- Что уже показано, хранится в `data/chat_seen.json`. Список общий для всех диалогов: его не сбрасывают ни «Новый диалог», ни перезапуск.
- Если ответ модели оборвался ошибкой или ты его остановил, новое покажется ещё раз.

**Изменения подтверждаешь ты.** Агент готовит карточку «было → стало» с кнопкой «Применить», для нескольких изменений есть «Применить все». Удалённые задачи уходят в `data/trash/`. Если в `[chat]` поставить `confirm_changes = false`, правки будут применяться сразу, но удаление всё равно требует подтверждения. Тексты писем для агента — данные, а не команды.

**Ширина чата.** Левый край чата можно тянуть мышью (от 340 до 1000 px). Работают и стрелки ←/→, если ручка в фокусе, с Shift шаг крупнее. Двойной клик возвращает ширину по умолчанию. Ширина запоминается в браузере.

**Экономия контекста.** Чтобы длинный диалог не раздувал запросы к модели:
- в истории остаются полные результаты инструментов только за последние 2 хода, старые заменяются короткой пометкой «скрыт, вызови снова»;
- история ограничена бюджетом ~40 тыс. символов (≈10k токенов), самые старые ходы выпадают целиком. Долгосрочное о тебе хранит память;
- снимок бэклога приходит в конце последнего сообщения, а не в системном промпте. Начало запроса не меняется от вызова к вызову, и провайдер кеширует его: это дешевле и быстрее;
- у задач для модели короткие id (`[[a5ae9ae9]]` вместо полного имени папки). Интерфейс сам разворачивает их в карточки;
- `list_tasks` отдаёт компактные строки (по умолчанию 20 задач), Excel и CSV приходят в формате TSV. Лист до 60 строк отдаётся целиком, больше — первые 30 строк с пометкой, как получить остальное;
- в памяти процесса хранится не больше 20 последних диалогов.

MailAgent отдаёт модели новый текст письма целиком, а цитату прошлой переписки сокращает до 1500 символов.

Нужны `langchain-openai` и `OPENROUTER_API_KEY`. Без них чат выключен, остальное работает.

### Настройки и память ассистента

Шестерёнка в шапке открывает настройки:
- **Профиль:** имя, фамилия, роль. Так Task Helpy к тебе обращается, и это имя ставится автором задач, созданных через чат. Подпись в письмах по-прежнему берётся из `owner` в `[chat.options]`.
- **Тема:** «Классическая» (светлая или тёмная, как в системе), «Латте» (светлая тёплая), «Иней» (светлая холодная), «Эспрессо» (тёмная тёплая), «Полночь» (тёмная холодная). Тема запоминается в браузере.
- **Память ассистента** хранится в `data/memory.json`: профиль, стиль общения, какие задачи ты берёшь в работу, устойчивые факты и персональные подсказки для пустого чата. Её можно посмотреть и очистить здесь же.

Как работает память:
- **Когда обновляется:** после 3 минут тишины (ни новых сообщений, ни взятых в работу задач) или после каждых 10 ответов ассистента. Обновляет та же модель, что ведёт чат, отдельным запросом в фоне.
- **Что видит модель:** новые реплики чата и журнал «взял в работу» (от кого задача, тип, приоритет, срок, сколько она ждала). Перенос «В работу», отменённый в течение 2 минут, в журнал не попадает.
- **Как используется:** память попадает в системный промпт. Ассистент подстраивает тон и длину ответов, может перейти на «ты», если ты сам так пишешь, и в конце ответа предлагает вероятный следующий шаг. Персональные подсказки становятся первыми кнопками в пустом чате.
- **Если модель недоступна,** реплики не теряются, попытка повторится позже.

Память подключается к любому классу чата, у которого есть метод `update_memory(memory, transcript) -> dict` с полями `style`, `preferences`, `facts`, `suggestions`. В `examples/chat_agent.py` он сделан через structured output.

### Статистика

Вкладка «Статистика» рядом с доской и календарём. Период выбирается сверху (7 / 30 / 90 дней, всё время), он общий для всех цифр ниже.

| Раздел | Что показывает |
|---|---|
| **Задачи** | сколько пришло и сколько выполнено, сколько не выполнено и просрочено сейчас, какая доля закрыта в срок; медианное время до взятия в работу и от письма до «Готово»; график «пришло / выполнено» по дням; от кого задачи и сколько из них закрыто; типы и приоритеты; от кого вы берёте в работу чаще; в какие дни недели закрываете |
| **Чат** | сколько вы пишете и какой длины, среднее время ответа; частые слова и повторяющиеся запросы; какие инструменты использовал Task Helpy; сколько предложенных изменений применено; сколько раз обновлялась память |
| **Токены** | всего, вход, выход, доля из кеша, в среднем на ответ в чате; по дням и по источникам (чат, память, разбор почты); по моделям |
| **Почта** | сколько писем обработано, сколько стали задачами и UPD, сколько пропущено и почему, ошибки, автоответы |

У каждого графика есть подсказка при наведении (или с клавиатуры: Tab и стрелки) и кнопка «Таблица» с теми же числами.

Откуда данные:
- **задачи** — из `task.json` на доске и в архиве, поэтому история по ним видна сразу;
- **почта** — из `state.sqlite3`;
- **токены, чат и взятие в работу** пишутся в `data/stats/events.jsonl` начиная с этой версии. Токены считаются колбэком LangChain (`examples/llm_usage.py`) для чата, памяти и MailAgent.

Модуль `mail_harness/stats.py` использует только стандартную библиотеку.

### Ответы в ветке → UPD

Если человек отвечает в уже существующей переписке (на исходное письмо, на автоответ, на твой ответ из чата или на уведомление), новая задача не создаётся. Ответ дописывается в исходную задачу как **UPD**:
- в UPD попадает только новый текст, цитата старой переписки отрезается;
- вложения из ответа сохраняются в папку задачи;
- автоответ на такое письмо не отправляется.

Как харнесс понимает, что это ответ в ветку: по заголовкам `In-Reply-To` / `References`, а если их нет — по тому же отправителю и теме с «RE:».

На карточке горит бейдж «UPD · Анна». После открытия задачи он становится спокойным «UPD ×N». В карточке задачи есть лента обновлений, в чате — строка «🔄 UPD по задаче…», Task Helpy про это знает. Выключить: `[backlog] link_replies = false`.

### Уведомления и очистка

- **«Взял в работу».** Когда переносишь задачу в «В работе», автору письма через 10 секунд уходит ответ в ту же ветку: «Егор Иванович взял Вашу задачу «…» в работу». Если нажать «Отменить», письмо не уйдёт. Уведомление отправляется один раз на задачу, статус виден в карточке («Автор уведомлён · 12:03»).
- **Очистка в 00:00.** Выполненные задачи убираются с доски в полночь. Если программа в это время была выключена или ноутбук спал, при следующем запуске убирается всё, что закрыто до сегодняшней полуночи. По умолчанию задачи переносятся в `data/archive/<дата закрытия>/` вместе с файлами.

Настройки в секции `[backlog]` конфига: `author_name` (Имя Фамилия по умолчанию, пока профиль в настройках не заполнен), `notify_in_progress`, `notify_delay`, `notify_template`, `cleanup_done = "archive" | "delete" | "off"`.

### Что лежит в `data/`

| Путь | Что это |
|---|---|
| `backlog/<id>/` | активные задачи: `task.json` и вложения |
| `archive/<дата>/`, `trash/<дата>/` | выполненные (после очистки в 00:00) и удалённые задачи |
| `dry_run/` | письма, которые ушли бы в боевом режиме |
| `memory.json` | профиль и память ассистента |
| `chat_seen.json` | какие задачи и UPD ассистент уже показал |
| `stats/events.jsonl` | журнал для статистики: токены, сообщения в чат, взятие в работу, применённые изменения |

Папка `data/` в `.gitignore`: там личные данные и переписка.

### Автозапуск (macOS)

```bash
python3 -m mail_harness service install          # dry-run
python3 -m mail_harness service install --live   # боевой режим
python3 -m mail_harness service status
python3 -m mail_harness service uninstall
```

После установки `serve` стартует при входе в систему и перезапускается при падении. Лог пишется в `logs/harness.log`, ключи берутся из `.env`. После изменения кода или конфига перезапусти: `service install` ещё раз.

## Скорость

Время самого харнесса без LLM — несколько миллисекунд на письмо (замер на локальном IMAP/SMTP-сервере). Что для этого сделано:
- **Имя компьютера для SMTP.** smtplib при каждом подключении ищет полное имя компьютера через DNS, и на части Mac это стабильно занимает 5 секунд. Харнесс берёт имя через `socket.gethostname()` мгновенно. Задать своё можно в `[smtp] local_hostname`.
- **Одно SMTP-соединение на все письма.** Автоответы, уведомления и ответы из чата идут через одно соединение. Перед отправкой его проверяет `NOOP`, при обрыве открывается новое. Сколько секунд держать соединение без дела, задаёт `[smtp] keepalive` (по умолчанию 120, `0` — новое соединение на каждое письмо).
- **Размеры писем одним запросом.** После поиска новых писем их размеры запрашиваются одним `UID FETCH`, а не отдельной командой на каждое письмо.

Задержку между приходом письма и его обработкой задаёт `[harness] poll_interval`. Пустой опрос ящика — это 2 команды IMAP, так что интервал можно смело ставить 10–15 секунд.

## Про Outlook / Exchange

- IMAP и SMTP должны быть **включены на сервере** для твоего ящика. В корпоративном Exchange их часто отключают. Проверяется командой `check`.
- Для Office 365 обычный пароль не подойдёт: нужен `auth = "xoauth2"` и токен в `token_env`. Как получить токен, зависит от организации.
- Имена папок могут быть на русском (`Отправленные`, `Входящие/Бэклог`), харнесс кодирует их сам. Точные имена показывает `folders`.
- Копию ответа в «Отправленные» можно класть через `imap.sent_folder`: SMTP сам её не сохраняет.
- Письмо читается через `BODY.PEEK`, поэтому в Outlook оно остаётся непрочитанным.
